# 逐字段确认脚本

Read this when running the field-by-field confirmation loop in `SKILL.md`.

## 通用规则

1. **一次只问一个字段**，等用户回答后再问下一个。
2. 字段名带 `*` 为**必填**；非必填可回答「跳过」或「不涉及」。
3. **不涉及占位**：用户跳过/不涉及 → 最终 PRD 该处写 **本需求不涉及**（保留章节/小节标题，不删除结构）。
4. **Brief 预填**：第一次 brainstorming 已明确的字段，先展示预填内容请用户确认或修改，不重复追问。
5. **流程图门控**：业务流程图、产品流程图必须先以文字列出流程（角色、步骤、分支、异常、起止），用户确认后再出画板图。
6. **埋点门控**：进入第五章前先问「本需求是否涉及埋点？」；否 → 第五章正文写 **本需求不涉及**。
7. **第一章最后生成**：「一、重点信息概述」由第二至七章已确认内容汇总生成，只追问无法推出的字段。之后第三、四、六章有任何改动，都重新生成第一章并请用户确认。

确认顺序：标题 → 二 → 三 → **（第二次 brainstorming）** → 四 → 五 → 六 → 七 → 一。

## 进入第四章前：第二次 brainstorming（方案设计澄清）

在进入「四、产品实现方案」逐字段确认之前，**必须先**用 `brainstorming` 做方案设计澄清，覆盖：

- 产品类型（App / 中台 / 通用），决定 4.2 用哪种图示
- 角色 × 场景矩阵
- 主流程与关键分支
- 页面/状态清单、页面层级与关联
- 异常与边界
- 数据指标口径（如有）

产出方案 brief 后，再按下方字段逐条确认。
