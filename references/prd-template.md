# 标准 PRD 模板（六章结构）

Use this structure when writing the final PRD body. Fields marked `*` are required.

Heading numbering uses `.` (dot), not `、`. Example: `一. 产品模块概述`, `1. 需求背景`.

## 标题

`xx域-xx模块-需求名称-版本号`

Example: `商品管理域-SKU管理模块-SKU标签优化-20260401`

---

## 二. 需求与背景分析

### *1. 需求背景

实际业务场景、用户痛点或需求

### *2. 需求目标（包含关键指标）

基于背景，在本次产品迭代中，业务希望达到的目的。需要与业务共识清楚，尽可能量化、细化

### *3. 目标用户

角色、场景、行为说明、权限说明

### *4. 核心价值（量化）

业绩、效率、成本、风险控制、体验、基础能力

### *5. 需求成本（预估）

预估投入资源（人力、服务费等），换算为 RMB

### 6. 竞品分析

大模块、核心模块、0-1 构建，需要有竞品分析。不涉及则写：**本需求不涉及**

---

## 三. 产品实现方案

### *1. 基础信息

组织、角色权限、数据权限，需要以用户视角

角色和场景说明：什么角色，预期什么，通过什么，实现什么

### *2. 业务流程图

以业务视角，角色在什么系统做什么操作，业务节点如何流转

- 基于业务流程图标记「新增」「修改」
- 针对调整的部分明确标记并说明
- 最终呈现：飞书画板泳道图（SVG）

### *3. 产品流程图

基于不同产品类型，输出不同的图示：

- 整体抽象模型
- App 产品：流程图和页面流转图
- 中台产品：系统层级图、角色时序图

最终呈现：飞书画板角色时序图（SVG）

### *4. 界面设计及功能说明

（1）原型图 + 功能布局

**硬性要求：** 这一节必须插入图片或 HTML 文件，放在标题正下方。只有文字、没有图片也没有 HTML 附件，本节不合格，不得发布。图片可以是现网截图或设计稿；HTML 须是可打开的单文件。二选一即可，文字不能代替附件。

（2）功能清单：功能点

（3）需求功能点逻辑描述

（4）交互设计描述

（5）异常场景

（6）案例说明

（7）场景是否涉及 Session 处理机制

（8）场景是否高并发

需要体现页面层级和页面关联性

## 五. 运营落地计划

### *1. 运营方案

运营角色、执行动作、观测指标；核心运营策略、异常处理方案

### *2. 执行节奏

整体产品上线运营计划

### *3. 反馈机制

如何收集用户反馈，反馈体量

### *4. 数据调整

历史数据是否需要调整，如果调整规则是什么，技术如何操作。不涉及则写：**本需求不涉及**
